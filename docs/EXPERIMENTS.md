# 이미지 임베딩 비교 실험

음식 추천에 쓸 이미지 임베딩을 세 가지 방식으로 만들어 비교했습니다.

**결론부터** — 사전학습 ResNet18 을 채택했습니다. 직접 학습한 오토인코더는 데이터가
부족해 유의미한 임베딩을 얻지 못했고, ResNet 도 변별력이 충분하지는 않지만
같은 계열의 음식을 찾아내는 수준은 됩니다.

---

## 실험 설정

| 항목 | 값 |
|---|---|
| 데이터 | 한식 사진 416장, 음식 151종 (음식당 평균 2.8장) |
| 평가 방법 | 기준 음식 하나에 대해 코사인 유사도 상위 5개를 확인 |
| 기준 음식 | 구이 · 갈비구이 |

같은 음식의 사진이 여러 장이면 벡터를 평균 내 대표 벡터로 썼습니다.

---

## 결과

### 1. 색 히스토그램 (딥러닝 아님, 대조군)

RGB 채널별 32빈 히스토그램 + 4×4 격자 평균 밝기 = 112차원.

```
1. 나물 · 고사리나물    +0.926
2. 만두 · 만두         +0.910
3. 국 · 미역국         +0.907
4. 김치 · 무생채       +0.906
5. 면 · 칼국수         +0.902
```

갈비구이와 고사리나물이 0.926. 색 분포만으로는 음식을 구분하지 못합니다.
유사도가 전부 0.9 위에 몰려 있는 것도 "전부 비슷하다" 고 말하는 셈이라 무의미합니다.

**용도** — 임베딩 → 저장 → 추천 경로가 도는지 확인하는 배관 점검용으로만 남겼습니다.

### 2. 컨볼루션 오토인코더 (직접 학습)

256×256 입력, 잠재 차원 128, 416장으로 150에포크 학습 (Colab T4).

```
1. 나물 · 미역줄기볶음   +0.454
2. 면 · 물냉면          +0.446
3. 전 · 감자전          +0.402
4. 무침 · 꽈리고추무침   +0.399
5. 국 · 시래기국        +0.387
```

갈색 구운 고기 기준인데 미역줄기볶음, 물냉면, 감자전이 나왔습니다. 색도 형태도
카테고리도 공통점이 없고, 구이 카테고리가 하나도 없습니다.

유사도 0.454~0.387 은 128차원 무작위 벡터끼리도 나올 수 있는 범위입니다.
**사실상 학습이 되지 않았다고 보는 것이 맞습니다.**

**원인** — 데이터 부족입니다. 오토인코더가 음식의 시각적 특징을 배우려면 최소
수천 장이 필요한데, 416장(음식당 2.8장)으로는 이미지를 뭉갠 평균값 정도만
학습됩니다.

### 3. 사전학습 ResNet18 (채택)

ImageNet 으로 학습된 ResNet18 의 분류층을 제거하고 512차원 특징을 추출.
학습 없이 추론만 수행.

```
1. 쌈 · 보쌈           +0.915
2. 김치 · 총각김치      +0.902
3. 볶음 · 주꾸미볶음    +0.894
4. 무침 · 홍어무침      +0.893
5. 찜 · 김치찜         +0.891
```

전부 **붉은 양념 계열의 고기·해산물 요리**입니다. 오토인코더와 비교하면 분명한
차이가 있고, "비슷한 종류의 음식" 을 찾아내고 있습니다.

다만 유사도가 0.915~0.891 로 다시 좁게 몰렸습니다. 상위 5개가 사실상 동점이라
"이것이 가장 비슷하다" 고 말하기는 어렵습니다.

**원인** — ImageNet 은 개·고양이·자동차를 구분하도록 학습됐지 한식 반찬을
구분하도록 학습되지 않았습니다. 음식 사진들이 벡터 공간의 좁은 영역에 몰립니다.

## 정리

| 방식 | 갈비구이와 비슷하다고 본 것 | 유사도 폭 | 평가 |
|---|---|---|---|
| 히스토그램 | 고사리나물, 만두, 미역국 | 0.926~0.902 | 색만 봄. 무의미 |
| 오토인코더 (직접 학습) | 미역줄기볶음, 물냉면, 감자전 | 0.454~0.387 | 학습 부족. 사실상 무작위 |
| **ResNet18 (사전학습)** | **보쌈, 총각김치, 주꾸미볶음** | **0.915~0.891** | **계열은 맞음. 변별력 부족** |

---

## 채택 근거와 한계

**ResNet18 을 씁니다.** 세 방식 중 유일하게 음식의 계열을 구분했고, 학습이 필요
없어 재현이 쉽습니다.

다만 임베딩의 역할을 제한했습니다. 추천 점수는 이렇게 계산됩니다.

```
prior = 0.6 × 임베딩점수 + 0.4 × 카테고리점수
score = 직접평가평균 × 커버리지 + prior × (1 - 커버리지)
```

- 구성원이 실제로 평가한 음식 → 평가 데이터가 점수를 지배합니다
- 아무도 평가하지 않은 음식 → 임베딩이 개입합니다

**이미지 임베딩은 콜드 스타트 보완용입니다.** 실제 평가가 있는 음식에는 평가
데이터가 훨씬 정확하고, 새로 등록한 음식이나 평가가 드문 음식에 의미 있는 점수를
매기는 것이 임베딩의 역할입니다. 위 실험 결과를 보면 이 제한이 타당합니다.

그리고 근본적으로, **생김새가 비슷하다고 맛 취향이 같지는 않습니다.** 김치찌개와
육개장은 둘 다 붉은 국물이라 임베딩이 가깝게 나오지만 취향은 갈립니다. 어떤 모델을
쓰더라도 이미지만으로는 넘을 수 없는 벽입니다.

## 재현 방법

```bash
# 배관 점검 (설치 불필요)
flask compute-embeddings --backend histogram
flask similar 1 --top 5

# 사전학습 ResNet
pip install -r requirements-ml.txt
flask compute-embeddings --backend resnet

# 직접 학습 오토인코더
python app/ml/train_autoencoder.py --images ./Data/KFoods/Foods --epochs 150
flask compute-embeddings --backend autoencoder --model models/autoencoder.h5
```

내 PC 에서 TensorFlow 가 동작하지 않으면 Colab 에서 계산해 가져올 수 있습니다.
